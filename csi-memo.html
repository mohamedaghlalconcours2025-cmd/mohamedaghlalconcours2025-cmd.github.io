CSI, recto : l'exercice (MCC)

Mémo de révision, 2AP

Dans l'ordre

  • Domaine → internes → externes → flux numérotés → contexte → MCC → relire le texte et cocher

Les 3 lignes de départ comme la prof

  • Domaine d'étude : « Gestion des ... » (sa fonction). L'ensemble des activités faites par les internes.
  • Acteurs internes : dans le domaine (services, employés). Peu : la prof fusionne quand le texte le permet.
  • Acteurs externes : hors du domaine, mais échangent avec lui (client, fournisseur, banque).

Flux

  • Lot d'informations entre un émetteur et un récepteur, dont au moins un interne.
  • Flèche émetteur → récepteur, libellé au-dessus, numéro entouré (ordre chronologique).
  • Un appel, un e-mail, une lettre, un message oral : c'est un flux.

L'information, pas l'objet

  • téléphone déposé → Demande de réparation
  • argent, chèque → Avis de règlement
  • colis, marchandise → Bon de livraison
  • Ses libellés : Demande de, Avis de, Accord/Refus de, Bon de

Dessin

  • Diagramme de contexte : le domaine dans un rectangle à trait plein, seulement les externes et leurs flux.
  • MCC (graphe des flux) : pas de rectangle ; interne = cercle à trait plein ; externe = cercle en pointillés ; tous les flux.
  • Matrice des flux : un tableau, émetteurs en lignes, récepteurs en colonnes, le flux dans la case.

Pièges

  • Oublier un acteur ou un flux. À la fin, relire le texte phrase par phrase, cocher chaque échange, et vérifier que chaque externe a ses flèches.
  • Entre deux externes (client → assurance) : pas de flux. L'acteur disparaît s'il ne parle qu'à des externes.
  • Vérifier, examiner, consulter, calculer, archiver : traitements internes, pas des flux.
  • Un fichier, une base de données, une personne seulement nommée : pas des acteurs.
  • Contexte : chaque flux externe-interne du MCC y figure ; un flux entre deux internes, jamais.
  • Flux interne déduit : seulement s'il faut pour que l'information arrive.

L'exemple du cours la vente

  • Internes : service commercial, service comptabilité, magasin. Externe : client.
  • Commande, Bon de commande, Facture, Avis de règlement, Règlement effectué, Bon de sortie, Bon de livraison.

CSI, verso : le cours (MCD)

Une phrase du cours + un exemple

Les 5 mots

  • Entité : une modélisation d'objets concrets ou abstraits utilisés dans un système. Rectangle. Salarié, Salaire. Pas un acteur.
  • Propriété (attribut) : une caractéristique ; une donnée élémentaire perçue sur une entité ou une association (Quantité dans Commander).
  • Occurrence : un cas réel de l'entité (le client Adam). Classe → instance.
  • Identifiant : une ou plusieurs propriétés qui identifient de manière unique chaque occurrence. Souligné. N° CIN, matricule. Jamais nom + prénom.
  • Relation (association) : modélise le lien entre entités. Ovale + verbe (Acheter).

Dimension nombre d'entités

  • 1 réflexive : Personne « est père de » Personne.
  • 2 binaire. 3 ternaire : Client, Voiture, MaisonDeVoiture (Acheter).
  • Plusieurs relations entre les mêmes entités : Posséder et Louer.

Dictionnaire de données

  • Un tableau, une ligne par propriété : N°, Code (Nom_Joueur), Désignation, Type (+ Règles).
  • Types : numérique, alphabétique, alphanumérique, date, monétaire.
  • Synonymes (Code_client = Ref_client) : un seul nom.
  • Polysèmes (« nom » du client et du fournisseur) : nom_client, nom_fournisseur.

Cardinalités

  • La participation des occurrences d'une entité dans une relation : (min, max).
  • 4 valeurs seulement : (0,1) (1,1) (0,n) (1,n). Jamais 2.
  • min : obligatoire ? 0 non, 1 oui. max : un seul ou plusieurs ? 1 ou n.
  • « Une occurrence de A est liée à combien de B, au min et au max ? » → écrite du côté de A.
  • Suivre le texte : « une seule » = (1,1) ; « plusieurs » = (1,n) ; 0 seulement si « peut ne pas », « aucun ».

Exemples

  • Salarié (1,1) Être affecté (1,n) Service
  • Joueur (1,1) Appartenir (1,n) Équipe
  • Client (1,n) Commander (0,n) Produit
  • Personne (0,n) Posséder (1,1) Voiture
  • Ville (0,1) Capitale de (1,1) Pays

Lire un MCD, puis le faire

  • « A peut-il avoir plusieurs B ? » Lire le max du côté de A : 1 = non, n = oui.
  • Texte → MCD : 1 dictionnaire ; 2 règles de gestion (les phrases qui donnent les liens) ; 3 entités + identifiants → relations → cardinalités.

Pièges MCD

  • Entité ≠ acteur. Attribut = caractéristique.
  • Nom + prénom n'est pas un identifiant.
  • Pas de (2,n), pas de 0 inventé.
  • Le type n'est jamais « nom ». La relation est un verbe.
